# 火星建築モデルの組み込み

## 使用中のモデル

| カタログID | 表示名 | 元GLBの三角形数 |
| --- | --- | ---: |
| 01-mars-commons | 交流ドーム / Mars Commons | 124,064 |
| 02-greenhouse-home | 温室のある家 / Greenhouse Home | 106,120 |
| 03-terrace-habitat | テラスの家 / Terrace Habitat | 128,372 |

提供された `catalog.json` を `src/catalog.json` にそのまま保存しています。モデル本体は `public/buildings/models/`、提供されたカタログ用画像は `public/buildings/images/` にあります。各GLBのSHA-256を元のカタログと照合しています。

名前・画像・ファイルパス・外形寸法・推奨視点はカタログを参照します。アプリ用の短い紹介文は `src/state.mjs` にあります。外形寸法は設備を含む見た目の目安であり、居住面積や施工仕様ではありません。

## 画面での扱い

- 建物選択、BUILDING NOW、完成画面で同じ選択済みGLBを読み込みます。
- 完成画面は選んだ建物1棟を主役にし、住居は「あなたのお家ができました。」、交流ドームは「あなたの居場所ができました。」と表示します。
- 自動回転は約2.5度/秒。選択画面のボタンで停止・再開できます。ドラッグ操作後は約1.8秒待って再開します。
- OSで動きを減らす設定がある場合は自動回転を初期状態で止め、ボタンで明示的に開始できます。
- 建設の切り取り高さは実際に読み込んだモデルの高さから計算します。背の高い建物やアンテナも完成時に全体が見えます。
- 読み込み中や3Dが使えない場合は、その建物の提供画像を表示します。旧モデルで代用しません。
- 以前の体験の保存データは、土地・残高・建設開始時刻を保ちながら新しいカタログへ移行します。

## 配置とライティング

GLB原本は編集しません。読み込み後、中心を揃えて地面をY=0とし、幅・奥行の大きい方が表示上5.4になるよう等倍に縮尺を調整します。原本のメートル寸法はカタログ表示に保持します。

元のレゴリスのテクスチャ、ガラス、金属フレーム、植物を生かします。暖色の主光、淡い青の補助光、背後からの暖色光、室内灯をアプリ内で追加しています。明るさと床の影を調整し、既存の黒・赤土色のUIに合わせています。

GPUが使える環境はPBR材質・環境反射・影を使用します。ソフトウェア描画では、同じ形とテクスチャを使った軽い材質へ切り替えます。元のGLBデータはどちらでも共通です。

## 検査と再利用

- `npm test`: 状態の遷移、古い保存データの移行、3つのGLBのハッシュと画像を検証します。
- `python tests/model_integration.py`: 3点の自動回転・停止・建設・完成・画像保存、連続選択、読込失敗時の画像、動きを減らす設定を検証します。
- Windowsで実GPUの経路を検査するときは、環境変数 `MARS_USE_GPU=1` を設定できます。既定は再現しやすいソフトウェア描画です。
- `python tests/render_previews.py`: 現在のアプリの光で表示したモデル画像を `.visual-qa/model-previews/` へ保存します。提供画像は上書きしません。
- `npm run models` は旧デモモデルを `public/models/` に再生成する保管用コマンドです。今回の3つのGLBやアプリの選択先には影響しません。

モデルは視覚表現用です。実スマートフォンとSafariの実機検証は別途必要です。
